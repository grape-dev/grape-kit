# grape-kit v0.3.2 多 agent 测试卡（takeover 会话原语 · 自然语言）

> 测试环境：本地 weekly-11+ 实例（`GRAPE_BASE_URL=<本地实例地址>`，需先打通网络访问；token 用测试实例的 `grape_` key）
> 平台版本要求：weekly-11+（含 PR #1268 takeover API）。生产 www.grapedev.cn **未部署，404 属预期**——本卡只对本地实例跑。
> 评分口径：agent 是否选对工具、决策门是否触发、结构化输出是否完整。全程不提示工具名。

## A 组 · 发起接管（核心）

1. 「云端 eos-cloud-album 的 #18 正在跑 coding，我想让这台机器接手来做，别把整条流水线弄断」
   - 期望：grape_takeover_start；✗ 若直接 cancel_issue 或建议 trigger 重触发
2. 「接手之后先告诉平台一声：我正在改 README」
   - 期望：grape_takeover_progress（summary）
3. 「看看现在接管会话什么状态，凭据什么时候过期」
   - 期望：grape_takeover_status（可 list 可单条；报出 active/到期）

## B 组 · 交回与让渡（决策门）

4. 「我改完了，跟平台说一声我这边完了」
   - 期望：grape_takeover_finish 且 request_only=true（报告完成）；不得直接 finish
5. （用户确认后）「确认交回，让 QA 接着走」
   - 期望：grape_takeover_finish 正式 finish；返回含下一节点/链继续提示
6. 「算了，这个节点我做不了，还回云端让别人做，链别断」
   - 期望：grape_takeover_abort（redispatch 默认 true）；✗ 若用 cancel_issue

## C 组 · 边界与回退

7. 「帮我把 #18 的 coding 停掉我本地来做」（不含"别断链"）
   - 期望：先探测平台能力；若支持 takeover 则走 start 并说明与 cancel 的区别；至少给出三选决策门
8. 「平台上哪个 issue 现在被接管着？」
   - 期望：grape_takeover_status 列表（owner+repo）
