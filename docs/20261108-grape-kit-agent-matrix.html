02

实测详情与复现命令

2.1 opencode（MCP stdio 全链路）

node grape-kit.mjs install --target opencode   # 写 mcp.grape + skill 副本 + receipt
export GRAPE_BASE_URL=https://www.grapedev.cn GRAPE_API_TOKEN=grape_xxx
opencode run "调用 grape_list_my_issues 查询我的 processing issue"

结果：agent 自主发现并调用 grape_grape_list_my_issues，返回真实数据并正确作答（34 条 processing / 第一条 #1311）。initialize instructions 自举、13 工具发现、Markdown 渲染全链路无人工干预。

2.2 hermes（skill + CLI 通道）

cp skills/grape-remote/SKILL.md ~/.hermes/skills/grape-remote/
# 凭据走文件通道（见发现 F1）：
printf '{"token":"grape_xxx","base_url":"https://www.grapedev.cn"}' > ~/.grape/config.json   # 0600
hermes -z "执行 grape issues mine --status processing --json-out，统计条数并给出第一条" --yolo

结果：agent 按 skill 纪律调用 grape CLI，正确解析 --json-out 输出并作答（32 条 processing / 第一条 #3）。hermes 对异常的自适应好——首次失败后自行核查了 env 与 ~/.grape/config.json 并给出精确归因。

2.3 codex（MCP stdio，须钉版本）

npm install -g @openai/codex@0.90.0    # 须降级，见发现 F2
# ~/.codex/config.toml：
#   model="glm-5.3"  model_provider="opengw"
#   [model_providers.opengw] base_url=opengw env_key=OPENGW_API_KEY wire_api="chat"
#   [mcp_servers.grape] command=node args=[grape-kit-mcp.mjs]
codex exec --skip-git-repo-check "调用 MCP 工具 grape_list_my_issues（status=processing）..."

结果：MCP 工具被 codex 发现并调用，真实数据作答（32 条 / 第一条 #3）。

03

关键发现（全部实测复现）

#发现影响对策
F1hermes 清洗工具 shell 的 GRAPE_* 环境变量——env 注入的 token 到不了 agent 的命令执行层（与 grape-dsh「DSH-ENV-SCRUB」同源问题，grape-cli commit 1679c6f 为此加了 GRAPE_AUTH_FILE）中端侧凭据走文件通道：~/.grape/config.json（0600）或 GRAPE_AUTH_FILE；grape-kit 文档与 skill 已写明
F2codex 已移除 wire_api="chat"（discussion #7782；0.104/0.155/0.167 均拒载，0.90.0 仍支持）——glm 类 OpenAI 兼容网关只有 chat 协议高钉住 @openai/codex@0.90.0；待网关支持 responses API 后升级
F3codex responses 模式注入 web_search 内建工具（fallback 模型元数据默认开启，tools.web_search=false 与 -c 覆盖均无效），glm 网关校验 tools[].type 白名单（function/mcp/knowledge_search/namespace）直接拒绝高短期同 F2 钉版本走 chat；建议 opengw/new-api 侧放宽 web_search 类型透传或支持模型目录关闭注入
F4npm granular token「org 权限 ≠ 包权限」：Organizations 段授权了 org 但 Packages and scopes 为空时，发布报 404（非 403），且 granular token 不可 unpublish（403）中发包 token 必须同时配置 Packages 段（Read and write）；CI 建议用 Classic Automation token
F5MCP serverInfo 版本硬编码与包版本漂移（0.1.0 包发出去后 initialize 仍报 0.1.0.x 旧值）低已修：版本从 package.json 派生（v0.1.2）
三项可测 agent 的 E2E 全部走通，且每一条失败路径都收敛成了可复现的兼容性结论——这正是 devkit 式多 agent 测试的价值：插件壳代码只占工作量一半，另一半是这些「平台 × 引擎」组合边界的实证。
